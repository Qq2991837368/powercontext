StepFun × seekdb：浏览器本地向量化的迷你知识库

技术说明 · Node.js 24.19.0 / seekdb-js 1.4.0 / Transformers.js 3.7.6 / ONNX Runtime Web 1.22

1. 方案概览

应用分为浏览器端与 Node 端。浏览器在 Web Worker 中加载 Xenova/bge-small-zh-v1.5（512 维，CLS pooling + L2 normalize），完成文本分块与 embedding；Node 端把 {id, text, embedding, metadata} 批量 upsert 到嵌入式 seekdb。查询时浏览器只编码 query，将查询向量与原始关键词交给 seekdb，由 hybridSearch 在库内完成向量 + 全文的 RRF 融合，客户端不参与融合或重排。模型权重本地托管，向量不离开设备，后端不做 embedding。

2. 推理后端与量化

  • 模型资产：q8 ONNX 24,010,842 B，fp32 ONNX 94,851,877 B；含 tokenizer/config 总文件体积 24,451,175 B（23.32 MiB）与 95,292,210 B（90.88 MiB），压缩比 3.90×。
  • 启动时显式探测 navigator.gpu.requestAdapter()；可用则优先 WebGPU，加载或推理失败时捕获异常并降级 WASM，UI 顶部横幅展示原因。
实测结论：同机同语料（28 篇 / 13 条标注查询）下，q8 跑在 ORT WebGPU EP 时数值不可靠：纯向量 Recall@5 从 WASM 的 80.1% 降至 21.8%，吞吐也从约 21 片段/秒降至 17 片段/秒。因此 INT8 显式路由到 WASM 并在 UI 说明；FP32 使用 WebGPU。既保留 WebGPU 优先能力，也保证 INT8 检索质量。

ORT 的 .mjs loader 不能从 Vite 的 public/ 目录动态导入（Vite 会报 “should not be imported from source code”）。实现改为 fetch 该文件并生成 Blob URL，.wasm 使用同源绝对 URL，开发与生产构建行为一致。

3. seekdb 内的混合检索

fulltextIndex: new FulltextIndexConfig('ngram2', { min_ngram_size: 2, max_ngram_size: 3 })
vectorIndex: new VectorIndexConfig({
  hnsw: { dimension: 512, distance: 'cosine' },
  embeddingFunction: null,   // 向量由浏览器提供
})

collection.hybridSearch({
  query: { whereDocument: { $or: [{ $contains: term }, ...] }, nResults },
  knn: { queryEmbeddings: embedding, nResults },
  rank: { rrf: {} },
  nResults,
  include: ['documents', 'metadatas', 'distances'],
})

中文查询按空白/标点拆词，长 CJK 串按 3 字切块（最多 8 项），以 $contains 构造全文条件；向量通道走 HNSW cosine。RRF 融合、排序、Top-N 截断全部发生在 seekdb 进程内。

4. 增量导入与索引刷新

导入流程：分块（默认 320 字 / 64 重叠）→ Worker 按 batch 8 向量化 → 前端按 16 条/批调用 POST /documents（不刷新）→ 全部写完调用一次 refresh_index()。新增片段刷新后立即可检索，接口返回服务端实测 writeMs / refreshMs。

嵌入式 seekdb 的原生引擎并发访问在 Windows 下会触发 0xC0000005。服务端用单一 Promise 队列串行化全部 /api 请求；响应很小，串行化不构成吞吐瓶颈。

环境：AMD Ryzen 7 6800H / RTX 3050 Ti Laptop，Chromium（WebGPU 可用），Node v24.19.0。质量集为 28 篇内置语料、13 条人工标注查询，指标取宏平均。

6. 取舍与边界

  • 体积口径统一按实际下载文件字节（含 tokenizer 与 config），不以参数数量估算。
  • INT8 与 FP32 各自建库，避免不同精度向量混用；切换精度时 UI 提示并自动新建集合。
  • 内置 28 篇语料与 13 条查询用于可复现评测；评测重建独立集合并保留原始 JSON。
  • 模型可用 npm run fetch:model 预下载，也可回退 hf-mirror / Hugging Face 远程拉取；推理始终在本地浏览器完成，不调用云端推理接口。
